# Standalone operations candidate

This source candidate adds a runnable collection API, native corpus handoff and
remote delivery lifecycle. It is not a release, deployment or model-quality
acceptance claim. The collection controller composes the existing command,
checkpoint, immutable result archive, corpus and outbox owners; it does not
introduce another crawl scheduler or database.

## Startup

Copy `examples/collection-service.toml`, replace its paths and configure the
native collector recipe with journal and continuation enabled. Configure models,
sources, permitted networking and optional extraction dependencies through that
recipe. Bind bearer and model/source secrets through the configured environment
names; secret values do not belong in TOML or API responses. Startup validates
recipes, credentials, optional corpus/outbox stores and the native collector
dependency assembly before accepting HTTP requests.

Create the service parent directory explicitly. The first invocation alone uses
`--create-service-store`; subsequent starts reopen the same private store.
Optional corpus, outbox and delivery destinations must already exist, created
explicitly through their native APIs. No startup creates or overwrites them.

```sh
python -m ghimera.service_command --config /absolute/service.toml \
  --max-config-bytes 1000000 --create-service-store
```

The packaged command is `ghimera-service`. The process reports readiness with its
actual bound address and policy digest, owns all background tasks and drains them
on SIGINT/SIGTERM within the configured grace policy. All routes require the
configured owner bearer. The HTTP listener admits loopback addresses only;
off-host access requires an operator-owned authenticated TLS reverse proxy.

## API

| Request | Behavior |
|---|---|
| `GET /health` | Current states, active/task counts, capacity, retained archive/checkpoint bytes and filesystem free bytes |
| `GET /manifest` | Effective non-secret service/startup configuration |
| `POST /runs` | JSON `ResearchRequest`; returns a durable job receipt before executing work |
| `GET /runs/<run-id>` | Durable status, native checkpoint/archive/corpus receipts and delivery identity |
| `POST /runs/<run-id>/pause` | Pauses queued work immediately or active research at its next completed checkpoint quantum |
| `POST /runs/<run-id>/resume` | Resumes a clean checkpoint, or resets the configured bounded archive-handoff retry allowance |
| `POST /runs/<run-id>/cancel` | Cancels and drains the owned task; preserves existing evidence and uncertain native calls |
| `POST /corpus/query` | JSON `{"text":"...","top_k":5,"languages":[]}`; native passage retrieval from the configured corpus |
| `GET /deliveries/<delivery-id>` | Optional configured native destination's durable ACK, or 404 |
| `PUT /deliveries/<delivery-id>` | Optional destination receives a complete native `DeliveryItem`; immutable readback precedes ACK |

Control POSTs have empty bodies. HTTP callers choose research intent/seeds, not
filesystem inputs, model endpoints, credential paths or output paths. Local file
research remains a caller-owned native command operation. Service job IDs and
request/result paths are generated by the service, retained in its private store
and bound to the exact service policy and collector recipe digest. Header/body,
connection, deadline, retained-job and active-work allowances are explicit.

Clean native checkpoints survive a process restart. Interrupted running or
pausing invocations become `held`; an older checkpoint is not permission to
repeat later external work. These jobs require the native recovery owner's
reconciliation and cannot resume through this API. Explicit cancellation is
terminal and does not erase originals. This candidate does not claim arbitrary
interrupted-session adoption.

Completed research is retained in the immutable native archive before corpus
or outbox handoff. Failed handoffs enter `handoff_pending`, retry with the
configured delay and durable attempt allowance, and can be retried after restart
without another crawl. The exact corpus acknowledgement is saved before outbox
admission so a lost enqueue acknowledgement reconstructs the same delivery
identity. Corpus and delivery receipts acknowledge persistence, not factual
correctness. A native partial/failed research outcome remains visible in its
archive receipt even when persistence completes.

## Remote delivery and retention

`RemoteDeliverySink` implements the existing final `DeliverySink` contract. It
uses the native pinned private JSON transport, including exact DNS address
admission, TLS verification, proxy/netrc suppression, no redirects, bounded
headers/bodies and a total call deadline. The configured destination receives
GET/PUT calls at `endpoint/<delivery-id>` and must return identical exact-target
ACKs after durable readback. This candidate admits explicitly approved private
addresses; it does not expand the transport to public destinations. See
`examples/remote-delivery.toml` for the safe inactive recipe.

The standalone delivery command `/2` accepts this remote destination in its
`destination` table. Credential environment names are configured separately from
source/model credentials. Its existing outbox worker handles outages, retries,
expired uncertain claims and duplicates. The collection service can expose a
native `DirectoryDeliverySink` as a receiving endpoint; storage identity and
capacity stay with that sink.

Worker `/1` retains its existing wire/digest and behavior. Worker `/2` adds an
explicit acknowledged age measured from actual acknowledgement time, not initial
enqueue time. After that age it may prune payloads only after fresh exact
destination readback. Optional bounded attempt-audit rotation retains the last
acknowledged attempt and the immutable delivery tombstone. Pending, exhausted
and uncertain payloads are never age-pruned. See
`examples/delivery-retention.toml`.

SQLite reuses freed pages. Optional configured compaction after a pruning count
uses native VACUUM with an explicit free-space admission allowance; it preserves
all remaining payloads, acknowledgements and immutable identity rows. It does not
erase deduplication tombstones or silently create new generations. The configured
tombstone/store capacities remain finite and report backpressure when exhausted.
Long-lived generation rollover, service-manager deployment, actual off-host TLS
destination acceptance and representative model/site/scale quality remain open.

## Verification record

Verification uses the existing Python 3.11 runtime and an absolute source path
for this candidate. Behavioral tests cover native command pause/restart/resume,
single service ownership, held interruptions, archive-only handoff retries,
durable corpus/outbox identity after a lost ACK, fresh native corpus retrieval,
real authenticated loopback HTTP controls and delivery, acknowledgement age and
audit rotation, and the native service subprocess startup/SIGTERM/restart.

Loopback model/encoder/source replies are protocol fixtures. Native SQLite,
FAISS, libcurl, archives, checkpoints, subprocess lifecycle and HTTP transport
run for real. This evidence does not establish live model accuracy, public-site
collection quality, unattended production deployment or off-host durability.

The bounded owning/importer run passed **176 tests in 163.03 seconds**, no
failures or skips, using `/tmp/chimera-c0-20261006/.venv/bin/python` **3.11.16**
and `PYTHONPATH=/tmp/ghimera-operations-20261008/src`. It selected collection
service, delivery retention/outbox/worker, private JSON methods, collector command,
command continuation, served models, embedding scoring, Ahmia and package boundary
test files. Installed OCR fixture inputs were `/usr/bin/tesseract`,
`/usr/share/tesseract/tessdata` and
`/usr/share/fonts/dejavu-sans-fonts/DejaVuSans.ttf`. No dependencies were installed.

After final same-instance restart, effective-manifest and durable request-admission
refinements, the same Python 3.11.16 interpreter/source passed the
**21 owning tests in 28.45 seconds**
without failures/skips. Ruff check and strict mypy passed for the ten changed
production modules; source/test formatting was checked separately. All pytest
temporary storage was on the owned real-volume

used scoped execution permission because the restricted sandbox prevents local

was used in those checks. These are bounded importer checks, not a full gate.
